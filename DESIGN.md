# DESIGN.md

## Структуры данных и алгоритмы

### Состояние игры и история попыток

-   Конфигурация новой игры (`Config`) хранится как объект с системой счисления и длиной числа:
    `src/models/models.ts`.
-   Текущее состояние раунда хранится в модуле `src/components/game.ts`: счётчик попыток `tries`,
    прошедшее время `gameTime`, таймер `timerIdx` и загаданное число `secret`. Цифры ещё
    незавершённой попытки собираются в массив `currentGuess`. Массив удобен здесь, потому что
    пользователь вводит цифры в отдельные поля с фиксированными позициями.
-   Результат проверки одной попытки описан интерфейсом `BullsAndCows` и представлен двумя
    массивами — `bulls` и `cows` в `src/models/models.ts`. Это позволяет UI вывести на какие
    именно позиции угаданы быки и какие цифры являются коровами.
-   История DOM-элементов создаётся в `src/components/history.ts`. Каждый новый результат добавляется
    в начало упорядоченного списка `<ol>`; фактическая визуальная история не дублируется в отдельном
    массиве состояния приложения. Отображение статуса цифры разделено на быка, корову и промах.
-   Рекорды сохраняются в `localStorage` под ключом `game-records-${base}-${length}` как массив
    объектов `GameRecord`; структура и сортировка описаны в `src/components/records.ts`. Так данные
    сохраняются между перезагрузками страницы.
-   Допустимые символы каждой системы счисления лежат в строках словаря `systems` в
    `src/models/models.ts`. Для проверки уникальности цифры ввода используется `Set` в
    `isValidGuess`, а валидатор создаётся один раз для конкретной системы в
    `createDigitValidator`.

### `evaluateGuess`

Функция находится в `src/functions/evaluateGuess.ts`. Сначала она приводит секрет и предположение к
нижнему регистру, чтобы результат не зависел от регистра букв шестнадцатеричной системы. Затем
один проход `reduce` по позициям предположения выполняет классификацию:

1. Если цифра предположения равна цифре секрета на той же позиции, она добавляется в `bulls`.
2. Иначе, если цифра присутствует в секрете, она добавляется в `cows`.
3. Если цифры нет в секрете, она не попадает ни в один массив.

Алгоритм рассчитан на допустимые уникальные секреты и не использует дополнительных счетчиков;
количество быков и коров получается непосредственно по массивам, собранным в строках выше.

### `countPossibleSecrets`

Функция находится в `src/functions/countPossibleSecrets.ts`. Количество вариантов вычисляется
рекурсивно по формуле размещений без повторений:

```text
A(m, n) = A(m, n - 1) * (m - n + 1)
A(m, 2) = m * (m - 1)
```

Для двоичной системы длина всегда приведена к 2: секрет может состоять только из двух возможных
цифр, поэтому итог — `2`. Для рекурсивных вызовов используется ключ `длина:система`, а в
интерфейсе функции предусмотрено поле `cache`. В текущей реализации количество вариантов для
базового случая не сохраняется в `cache`; результат каждого нового ключа поэтому вычисляется
рекуррентно заново. Ограничения длины и основания (в частности, длина не больше 6) делают
максимальную глубину рекурсии небольшой.

## Сложность

| Функция                                | Сложность                                                                                 | Обоснование                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret(length, base, random)` | O(length²)                                                                                | Цифры берутся из массива `digitsArr`; на каждой итерации длины числа `splice(index, 1)` копирует оставшуюся часть массива. Для `length <= 6` список короткий, но асимптотически удаление даёт дополнительный линейный фактор. Добавление символов строки также входит в O(length). Для `bin`, фактически имеющей две цифры, работа занимает O(1). |
| `evaluateGuess(secret, guess)`         | O(length²)                                                                                | Функция выполняет один проход длины числа, но для каждой небыка проверяет наличие цифры через `secret.includes(curr)`, что в худшем случае просматривает ещё `length` символов. Поэтому верхняя оценка O(length²); при ограничении длины 2–6 это только малая фиксированная константа. Дополнительная память O(length) на массивы быков/коров.    |
| `isValidGuess(guess, length, base)`    | O(length)                                                                                 | После проверок длины строится `Set` за O(length), затем за один проход проверяются все символы валидатором `createDigitValidator`. В алфавитах максимум 16 символов, поэтому поиск допустимой цифры считается O(1).                                                                                                                               |
| `countPossibleSecrets(length, base)`   | O(length) по времени и O(length) по памяти вызовов, после чего O(1) дополнительной памяти | На каждой рекурсии длина уменьшается на единицу до базового случая `length === 2`; ключевого кэширования на вычисленном в данный момент значении нет. В проекте длина ограничена 2–6, а размер алфавита ограничен 16, поэтому фактическое время выполнения мало и не зависит от большого входа.                                                   |

## Принципы чистого кода

-   **Разделение ответственности и модульность.** Логика правил вынесена из DOM-компонентов в
    отдельные функции: `generateSecret`, `evaluateGuess`, `isValidGuess` и
    `countPossibleSecrets` в `src/functions/`. Компоненты `src/components/game.ts`,
    `src/components/history.ts` и `src/components/records.ts` отвечают соответственно за игровой
    раунд, историю и сохранённые результаты.
-   **Малые функции с понятными именами.** Служебные операции UI выделены в короткие функции
    `choice` и `group` в `src/components/settings.ts`, а создание общей строки результата в
    `src/components/game.ts` вынесено в вложенную функцию `createStat`. Её имя прямо описывает
    результат, а не реализацию.
-   **Единая ответственность функции и предсказуемый результат.** `evaluateGuess` только проверяет
    предположение и возвращает `BullsAndCows`; `isValidGuess` только сообщает, допустима ли
    попытка; `countPossibleSecrets` только вычисляет число размещений. Побочные эффекты и изменение
    DOM оставлены компонентам.
-   **Неизменяемые входные данные конфигурации.** В `src/components/settings.ts` новый объект
    конфигурации создаётся через spread-объединение при смене системы или длины, вместо прямого
    изменения нескольких полей. Это снижает риск непреднамеренного изменения предыдущего состояния.
-   **Повторное использование и параметризация.** `choice`/`group` в
    `src/components/settings.ts` и аналогичные функции в `src/components/records.ts` создают
    однотипные элементы управления без дублирования разметки. Общие элементы DOM собраны в
    `src/ui/dom.ts`: `el` строит HTML-элемент, а `text` создаёт текстовый узел.
-   **Типобезопасность.** Общие типы состояния вынесены в `src/models/models.ts`: `Config`,
    `BullsAndCows`, `GameRecord` и ограниченный тип `Base`. Например, `createDigitValidator`
    принимает именно `Base`, а компоненты не передают произвольную строку как название системы.
-   **Проверка инвариантов на границе.** Чистые функции правил проверяют входные данные и бросают
    понятную ошибку `Incorrect Data`, например в `src/functions/evaluateGuess.ts`,
    `src/functions/generateSecret.ts` и `src/functions/isValidGuess.ts`. Это выявляет некорректные
    вызовы до начала вычислений.
-   **Проверяемость через юнит-тесты.** Правила вынесены в изолированные функции, поэтому для них
    существуют отдельные тесты рядом с реализацией: `evaluateGuess.test.ts`,
    `isValidGuess.test.ts`, `generateSecret.test.ts` и `countPossibleSecrets.test.ts`. Тесты фиксируют
    как корректные сценарии, так и обработку некорректных данных.
